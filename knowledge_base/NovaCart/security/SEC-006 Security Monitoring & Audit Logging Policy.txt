Purpose
This document defines the official Security Monitoring & Audit Logging Policy of NovaCart Technologies Pvt. Ltd. (hereinafter referred to as "NovaCart"). It establishes standardized enterprise procedures, monitoring principles, mandatory audit logging requirements, event review workflows, log protection controls, alert escalation pathways, operational responsibilities, and business rules governing the continuous monitoring, recording, review, protection, and retention of security-related activities across NovaCart systems, user accounts, and business operations.
As a core security policy (SEC-006) in the Security module of the NovaCart Enterprise Knowledge Base (NEKB), SEC-006 coordinates continuous security oversight across the Security Information and Event Management platform (shield.novacart.internal), Identity & Access Management (auth.novacart.internal), Audit Log Vault (audit.novacart.internal), Customer Support (crm.novacart.internal), and Payment Ledgers (ledger.novacart.internal), operating in strict operational alignment with COMP-001 through COMP-004, SUP-001 through SUP-005, ORD-001 through ORD-005, SHIP-001 through SHIP-007, PAY-001 through PAY-006, REF-001 through REF-006, PROD-001 through PROD-006, SEC-001, SEC-002, SEC-003, SEC-004, and SEC-005.
Scope
This policy applies universally across all technology platforms, cloud infrastructure nodes, microservice APIs, database environments, customer support portals, payment microservices, employee workstations, and physical facilities operated by NovaCart across India, Singapore, and the United Arab Emirates.
Coverage Includes
* Continuous monitoring of user authentication, administrative access, privilege escalations, financial operations, support agent activities, customer profile updates, and API interactions.
* Audit log generation, timestamp synchronization, masking standards, and cryptographic log integrity protection.
* Centralized log ingestion, real-time alert correlation, severity classification, and escalation workflows.
* Periodic internal security reviews, log auditing schedules, compliance reporting, and audit finding remediations.
* Standardized audit log retention schedules, Write-Once-Read-Many (WORM) storage, access restrictions, and secure log disposal.
Out of Scope
* Detailed real-time fraud scoring algorithms and chargeback representment mechanics (governed by PAY-004 and SEC-004).
* Emergency containment, threat eradication, and CSIRT response execution during active security breaches (governed by SEC-005).
Security Monitoring & Audit Logging Overview
Continuous security monitoring and immutable audit logging form the backbone of NovaCart's security governance architecture. Effective monitoring provides real-time visibility into operational activities, enables rapid identification of anomalous behavior, and provides tamper-evident audit trails necessary for forensic investigations (SEC-005), fraud detection (SEC-004), and statutory compliance.
Core Monitoring Principles
1. Ubiquitous Logging Coverage: All critical systems, customer authentication endpoints, financial transaction ledgers, administrative interfaces, and data vaults must generate continuous audit logs.
2. Immutable Log Integrity: Audit records must be protected against unauthorized modification, deletion, or truncation by any user, including system administrators with elevated privileges.
3. Least Privilege Log Access: Access to centralized audit logs is restricted strictly to authorized Security Audit Personnel on a verified need-to-know basis (SEC-002, SEC-003).
4. Proactive Event Analysis: Security telemetry is monitored continuously through automated correlation rules, transforming raw log data into actionable security alerts.
Monitoring Principles
NovaCart's security oversight framework relies on four core operational principles:
* Centralized Telemetry Ingestion: Audit logs generated by distributed microservices, databases, edge gateways, and employee portals must ingest continuously into shield.novacart.internal via secure, encrypted channels.
* Universal Clock Synchronization: All system clocks across the enterprise must synchronize continuously with NovaCart's primary Stratum-1 Network Time Protocol (NTP) servers using UTC time standards to ensure accurate event correlation across systems.
* Privacy by Design in Logging: Log streams must automatically sanitize and mask Class 3 (Confidential) and Class 4 (Restricted) data elements—such as passwords, payment card numbers, CVVs, and raw government IDs—prior to storage in log vaults (SEC-003, PAY-006).
* Continuous Oversight: Security monitoring operates 24 hours a day, 7 days a week, combining automated SIEM analysis with dedicated Security Operations Center (SOC) review queues.

	Audit Logging Standards
All system components emitting audit logs to audit.novacart.internal must adhere to standardized field structures and formatting requirements:
Mandatory Audit Log Elements
Every audit log record must contain the following core fields:
* Timestamp: High-precision UTC timestamp accurate to the millisecond.
* Event Identifier: Unique cryptographic Event ID (EVT-XXXXXXXX).
* Event Category & Action Code: Standardized classification tag (e.g., EVT-AUTH-LOGIN_SUCCESS, EVT-FIN-REFUND_APPROVED).
* Subject Identity: Authenticated User ID, Employee ID, or System Service Account ID initiating the action.
* Source Context: Source IP address, geographic location tag, device fingerprint, and User-Agent string.
* Target Context: Affected entity ID (e.g., Customer ID, Order ID, SKU ID, Database Table).
* Action Outcome: Binary status (SUCCESS or FAILURE) alongside explicit error or failure codes.
* Severity Score: Numeric risk rating assigned by the generating system (0 to 100).

	Log Review & Analysis Procedures
Automated SIEM monitoring is supplemented by structured human log reviews executed by the Information Security team:
1. Daily Operational Reviews: Security Operations Center (SOC) analysts perform daily reviews of high-priority alert digests, failed administrative logins, privileged access logs, and unusual bulk API queries.
2. Weekly Behavioral Trend Analysis: Security Specialists analyze weekly trend reports covering support agent account modification spikes, manual refund overrides (REF-005), and unexpected geographic login velocity changes.

	Audit Log Retention & Protection
To preserve evidentiary value and satisfy statutory governance standards, audit records are protected by stringent technical and operational controls:
Log Integrity & Protection Standards
* Write-Once-Read-Many (WORM) Storage: Centralized audit logs are written to immutable WORM storage buckets (audit.novacart.internal). Once written, records cannot be modified, overwritten, or deleted by any system user or administrative role.
* Cryptographic Hashing: Log archives are hashed continuously using SHA-256 algorithms, generating cryptographic ledger chains to detect any unauthorized log tampering, truncation, or gap injection.
* Strict Access Segregation: Access to read audit logs is granted exclusively to designated Security Audit Engineers using dedicated, MFA-authenticated auditor roles (ROLE_SEC_AUDITOR). System administrators (ROLE_SYS_ADMIN) are strictly blocked from viewing or managing audit log vaults (SEC-002).

	Internal Security Reviews & Audits
NovaCart conducts continuous internal security reviews to validate operational compliance across all departments:
1. Quarterly Internal Access Audits: Security Audit Engineers review all assigned RBAC roles, privileged access entitlements (SEC-002), and active support agent permissions, forcing revocation of stale or residual access rights.
2. Randomized Support Action Sampling: On a monthly basis, Information Security randomly samples $1\%$ of customer address changes, manual refund approvals (REF-005), and account unlocks executed in crm.novacart.internal to verify supporting ticket justification.
3. Audit Finding Management & Remediation:
   * Security audit findings are logged as formal remediation tasks in shield.novacart.internal.
   * Critical Findings: Must be remediated within 7 calendar days.
   * Major Findings: Must be remediated within 14 calendar days.
   * Minor Findings: Must be remediated within 30 calendar days.
Employee Responsibilities
All NovaCart employees, contractors, and technical staff maintain explicit responsibilities regarding audit logging and monitoring:
1. Adherence to Instrument Operations: Conduct all business operations exclusively through official, logged enterprise systems (crm.novacart.internal, ledger.novacart.internal). Executing corporate tasks via unmonitored shadow IT systems is strictly prohibited.
2. Prohibition of Log Bypassing: Technical staff are strictly forbidden from disabling, suppressing, or modifying audit logging configurations on production servers or microservices.
3. Prompt Alert Escalation: Report any suspected audit gap, missing log stream, or log anomaly to the Security Operations Center immediately.

	Business Rules
Rule 1: Mandatory WORM Protection for All Audit Logs
All audit log streams ingested by audit.novacart.internal must automatically transition to Write-Once-Read-Many (WORM) storage. System configurations permitting manual deletion, truncation, or editing of audit records by any user role—including system administrators (ROLE_SYS_ADMIN)—are strictly prohibited.
Rule 2: Automatic Alert Generation on Log Stream Disruption
If a primary logging agent or microservice log stream ceases emitting telemetry for more than 5 minutes, shield.novacart.internal must automatically trigger a High-Severity Security Alert (ALT-HIGH) to alert SOC analysts to a potential log suppression attempt or infrastructure failure.
Rule 3: Absolute Masking Mandate for Restricted Data
Under no circumstances may raw passwords, payment card numbers (PANs), CVVs, or full unmasked government IDs be written to standard log files. Automated pre-ingestion sanitization parsers must drop or mask non-compliant fields prior to log commit (SEC-003, PAY-006).
Rule 4: Mandatory 7-Year Retention for Core Security Telemetry
All authentication, administrative access, financial transaction, support agent action, and data access logs must be retained in secure, queryable storage for a mandatory period of 7 years to support legal, statutory, and forensic requirements.
Exception Handling
* Temporary Logging Bypass During Emergency Infrastructure Maintenance: If an emergency system recovery requires temporarily running a database or microservice in a reduced logging state, the action requires explicit, documented co-signoff from the CISO and VP of Infrastructure in incident.novacart.internal. The maintenance window cannot exceed 4 hours, and full logging must be restored and verified immediately thereafter.
* Remediation SLA Extension Approval: If a technical audit finding cannot be remediated within its assigned SLA due to complex vendor software dependencies, the department head must submit a formal extension request to the CISO. The CISO may grant a single extension of up to 14 days, provided temporary compensating security controls are implemented.
Practical Examples
Scenario 1: Detection and Investigation of Support Agent Bulk Data Access
1. A Customer Support Representative (CSR) uses crm.novacart.internal to view customer order histories.
2. The agent executes 60 unmasking actions for customer contact details within a 30-minute window, exceeding the standard baseline threshold of 10 views per hour.
3. shield.novacart.internal correlates the events and generates a High-Severity Alert (ALT-HIGH): "Anomalous Bulk PII Unmasking Detected - Agent ID #CSR-88201."
4. SOC Analyst receives the alert within 5 minutes, reviews the audit log trail in crm.novacart.internal, and notes the agent has no corresponding customer inquiry tickets open for those accounts.
5. SOC Analyst temporarily suspends the agent's session tokens (SEC-002) and escalates the incident to Security Management for an internal misuse investigation (SEC-005).
Scenario 2: Detection of Log Tampering Attempt on Infrastructure Server
1. An unauthorized actor gains access to a staging server node and attempts to execute a command to truncate /var/log/audit.log to hide malicious activity.
2. The local host-based security agent intercepts the file modification attempt, blocks the command, and emits an immediate alert payload to shield.novacart.internal.
3. Simultaneously, because central logs are shipped in real time via encrypted TLS 1.3 streams to immutable WORM storage (audit.novacart.internal), all log entries recorded prior to the truncation attempt remain fully intact and untampered.
4. The SIEM correlates the event, triggers a Critical Alert (ALT-CRITICAL), and CSIRT initiates automated node isolation (SEC-005).
Frequently Asked Questions (FAQs)
Q1: Are my customer support phone calls and live chat messages monitored and logged?
Answer: Yes. All customer support interactions—including live chat transcripts, email tickets, and customer phone call recordings—are logged and retained in crm.novacart.internal for quality assurance, dispute resolution, and security auditing purposes. Access to these logs is restricted strictly to authorized support leads and security personnel (Refer to SUP-001, SEC-003).
Q2: What happens if a system administrator tries to delete security logs to hide an error?
Answer: Audit logs are transmitted in real time to centralized, Write-Once-Read-Many (WORM) storage buckets (audit.novacart.internal) protected by cryptographic hashing. System administrators do not possess technical permissions to delete or alter these immutable records. Furthermore, any attempt to tamper with local log streams triggers an immediate Critical Security Alert (ALT-CRITICAL) to the Security Operations Center (Refer to SEC-002, SEC-005).
Q3: How long does NovaCart keep records of my account logins and order activities?
Answer: In accordance with our enterprise data retention standards, core security telemetry—including authentication logs, account changes, payment records, and order transaction trails—is retained securely for 7 years. This ensures complete auditability for legal, financial, and regulatory compliance (Refer to SEC-003, PAY-005).
