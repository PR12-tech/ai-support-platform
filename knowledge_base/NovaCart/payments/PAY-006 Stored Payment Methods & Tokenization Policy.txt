Purpose
This document establishes the official enterprise policy, security architecture, token lifecycle standards, customer consent requirements, and compliance rules governing stored payment credentials at NovaCart Technologies Pvt. Ltd. (hereinafter referred to as "NovaCart"). It defines the protocols for tokenizing credit cards, debit cards, UPI mandates, and digital wallets, ensuring zero storage of raw primary account numbers (PANs) or sensitive authentication data while providing friction-free, one-click checkout experiences.
As a core security and financial governance policy (PAY-006) in the NovaCart Enterprise Knowledge Base (NEKB), PAY-006 enforces technical controls across checkout microservices (api.novacart.internal/pay), the Identity and Access Management portal (auth.novacart.internal), and certified Payment Gateway (PG) token vaults, operating in strict alignment with COMP-001 through COMP-004, SUP-001 through SUP-005, ORD-001 through ORD-005, SHIP-001 through SHIP-007, and PAY-001 through PAY-005.
Scope
This policy applies universally across all customer interfaces (Web, Mobile Applications), payment gateways (Razorpay, Stripe, PayU, Telr), and operating jurisdictions (India, Singapore, UAE) where customers save, manage, or execute transactions using stored payment credentials.
Coverage Includes
* Card-On-File (COF) tokenization for Credit and Debit cards (Visa, Mastercard, American Express, RuPay).
* Tokenization of recurring payment mandates (UPI AutoPay, e-Mandates, BNPL auto-debit).
* Customer explicit consent capture, management, and revocation workflows.
* Token creation, validation, lifecycle maintenance, automated renewal, and secure deletion.
* PCI-DSS Level 1 compliance, token vault isolation, and role-based access control (RBAC).
Out of Scope
* Direct transaction clearing and authorization workflows (governed by PAY-001).
* Stored platform store credits, digital gift cards, and NovaCart Wallet balances (governed by PAY-001).
Stored Payment Methods Overview
To optimize checkout conversion and streamline repeat purchases, NovaCart allows registered customers to securely save payment credentials. To protect customer financial data and comply with global regulatory mandates (such as RBI Card-on-File Tokenization rules in India, PCI-DSS Level 1 globally, and regional privacy statutes), NovaCart strictly prohibits storing raw, unencrypted payment credentials on any internal server or database.

Core Operational Principles
1. Absolute Tokenization Mandate: No raw Primary Account Numbers (PANs), Card Verification Values (CVV/CVC), or bank account PINs are ever received, processed, or stored on NovaCart infrastructure.
2. Explicit Informed Consent: Credentials are saved exclusively when a customer provides explicit, active opt-in consent during checkout or within account settings.
3. Issuer-Backed Cryptographic Tokens: Saved payment instruments are represented solely by surrogate, algorithmically generated tokens supplied directly by card networks or certified gateway vaults.
4. Unconditional Customer Control: Customers retain absolute authority to view masked saved instruments, update billing metadata, or instantly delete saved payment tokens at any time.
Tokenization Overview
Tokenization is a security process that replaces sensitive payment credential data (such as a 16-digit credit card PAN) with a mathematically un-linkable, surrogate alphanumeric string known as a Payment Token.

Domain-Locked Token Security
Tokens generated for NovaCart are Domain-Locked and Merchant-Locked. A token created for NovaCart cannot be utilized by any third party or used on any other e-commerce platform, rendering stolen tokens completely valueless to malicious actors.

	Payment Method Registration Process
The end-to-end tokenization registration workflow executes seamlessly during transaction processing:
1. Consent & Input: During checkout, the customer enters card details in an encrypted, PCI-DSS compliant client-side iframe hosted directly by the certified Payment Gateway. The customer checks "Save this card."
2. Gateway Handshake & Tokenization Call: Upon 3D Secure / OTP authorization, the Payment Gateway transmits the raw card payload to the relevant Card Network Token Service (e.g., Visa Token Service).
3. Token Generation: The Card Network generates a unique Merchant-Locked Payment Token (TKN-XXXXX) along with masked display metadata (Card Brand, Last 4 Digits, Expiry Month/Year).
4. Token Persistence: The Payment Gateway returns the token and display metadata to api.novacart.internal/pay. NovaCart writes the token and display metadata to auth.novacart.internal. Raw card data never touches NovaCart databases.
5. Customer Confirmation: The checkout screen updates, displaying the saved card card-face graphic (e.g., Visa ending in 4821, Exp 08/28).

	Payment Method Update & Removal Process
1. Card Expiry & Automated Account Updater (AAU)
NovaCart integrates with Card Network Automated Account Updater (AAU) services (e.g., Visa Account Updater, Mastercard AB) managed via gateway partners:
* When a saved card expires or a issuing bank issues a replacement card (due to expiration or lost card replacement), AAU services automatically push the updated token and expiry date to api.novacart.internal/pay.
* The saved card details update seamlessly in the customer's account without requiring manual re-entry.
2. Manual Removal Process
A customer may delete any saved payment method at any time:
1. Customer navigates to Account Settings $\rightarrow$ Saved Payment Methods.
2. Customer clicks Remove next to the targeted payment instrument.
3. System prompts confirmation: "Are you sure you want to delete Visa ending in 4821?"
4. Upon confirmation, api.novacart.internal/pay sends an asynchronous API revocation request (POST /v1/tokens/revoke) to the Payment Gateway vault and permanently deletes the token record from auth.novacart.internal.
5. The saved card graphic disappears from the user interface immediately.

	Business Rules
Rule 1: Absolute Prohibition of CVV/CVC Storage
Card Verification Values (CVV/CVC/CVV2) or bank PINs must never be stored under any circumstances, even temporarily after transaction authorization. CVV entry is required for individual one-click checkouts unless regional card network rules explicitly permit frictionless CVV-less tokenized transactions.
Rule 2: Account Deletion Token Purge Rule
When a customer closes their NovaCart user account, auth.novacart.internal triggers an automated batch job that issues API revocation commands for all associated payment tokens across all gateway vaults and permanently purges local token metadata within 24 hours.
Rule 3: Security Freeze Token Lock
If an account is flagged for suspicious login activity or account takeover (ATO) by shield.novacart.internal, all associated saved payment tokens transition immediately to TOKEN_SUSPENDED status, blocking one-click checkout until identity verification is satisfied (Refer to SEC-001, SEC-004).
Exception Handling
* Gateway Token Vault Migration: If NovaCart transitions or adds a primary Payment Gateway provider, tokens are migrated between PCI-DSS Level 1 certified vaults using secure server-to-server bulk token migration protocols, ensuring zero disruption to customer saved cards.
* Revoked Token Transaction Attempt: If a customer attempts a checkout using a token that was recently revoked or invalidated at the issuing bank, the gateway returns error code TOKEN_INVALID. The checkout screen seamlessly prompts the customer to re-enter card details or select an alternate payment method (Refer to PAY-002).

Frequently Asked Questions (FAQs)
Q1: Does NovaCart store my actual 16-digit credit card number on its servers?
Answer: No. NovaCart strictly complies with PCI-DSS Level 1 and regional card tokenization regulations. Your actual 16-digit card number is converted into an encrypted, surrogate "Payment Token" by card networks (Visa, Mastercard, Amex, RuPay). NovaCart stores only this secure token and masked display information (e.g., Last 4 digits) (Refer to PAY-001).
Q2: What happens to my saved cards if I delete my NovaCart account?
Answer: When you close your NovaCart account, our system automatically issues revocation commands to all payment gateway vaults to cancel your stored tokens and permanently purges all associated display metadata from our servers within 24 hours (Refer to SEC-001).
Q3: Can a saved token be stolen and used on another website?
Answer: No. Payment tokens generated for NovaCart are cryptographically "Domain-Locked" and "Merchant-Locked." A token created for NovaCart is completely invalid and unusable on any other website or platform.
